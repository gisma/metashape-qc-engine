# Orthomosaic Stability Manual

## Purpose

This workflow analyzes the stability of UAV orthomosaics generated by repeated Metashape builds.

The central assumption is that a UAV orthomosaic is not a direct sensor image. It is a synthetic image product generated from overlapping photographs, camera alignment, tie points, a projection surface, seamline selection, blending and export settings.

Therefore, before an orthomosaic is used for fine-scale interpretation or change detection, the workflow asks a prior question:

Can this image area be reproduced reliably by repeated photogrammetric processing?

The current test site is a raised bog area with ditches, sparse trees and lying deadwood. It is not a forest canopy test site. The structural problem is still relevant, because small terrain objects, ditch edges, deadwood, isolated shrubs and sparse trees can create local projection and stitching instability.

## Current workflow status

The current workflow consists of three parts.

First, `reproducibility_runner.py` creates repeated Metashape builds from a base YAML configuration. It can also run several processing variants.

Second, each variant produces several orthomosaics. These orthomosaics are not assumed to have identical raster extent. Metashape can generate slightly different output dimensions even when the same input data and nominal settings are used.

Third, `ortho_stability_analyzer.py` brings all orthomosaics onto a common canonical analysis grid and computes stability products.

## Canonical analysis grid

A canonical analysis grid is a shared raster grid used only for analysis.

It is necessary because Metashape orthomosaics may differ slightly in size or extent. Direct raster subtraction only works when all rasters have identical dimensions, geotransform and projection. If one orthomosaic has 3640 columns and another has 3646 columns, direct pixel-by-pixel comparison is invalid.

The analyzer therefore warps all orthomosaics to one shared grid before computing statistics.

The current default is `union`.

`union` means that the analysis grid covers the full combined extent of all orthomosaics. This keeps variable border support visible. Areas that appear in only one replicate are not discarded; they become visible through the `valid_count` layer.

Other possible modes are:

`intersection`: only the area covered by all orthomosaics is analyzed. This is useful for pure pixel comparison, but it hides support instability at the borders.

`reference`: all orthomosaics are aligned to one selected reference orthomosaic. This is useful for quick tests, but it treats one output as the spatial frame.

For the current reproducibility question, `union` is the most informative mode.

## Output structure

The analyzer writes the following products:

```text
stability_union/
  canonical_grid.json
  summary.csv
  aligned/
    flat_mesh/
      rep_001_aligned.tif
      rep_002_aligned.tif
    light_mesh/
      rep_001_aligned.tif
      rep_002_aligned.tif
    moderate_mesh/
      rep_001_aligned.tif
      rep_002_aligned.tif
  variants/
    flat_mesh/
      valid_count.tif
      median_ortho.tif
      mad_rgb.tif
      rmse_to_median.tif
    light_mesh/
      valid_count.tif
      median_ortho.tif
      mad_rgb.tif
      rmse_to_median.tif
    moderate_mesh/
      valid_count.tif
      median_ortho.tif
      mad_rgb.tif
      rmse_to_median.tif
```

The `aligned` rasters are analysis copies of the original orthomosaics. They are not new Metashape products. They are warped onto the canonical grid so that all later comparisons are valid.

The files in `variants/` are the actual stability products.

## Explanation of summary values

The `summary.csv` contains one row per variant.

### `variant_id`

The processing variant.

Current variants:

`flat_mesh`: low face count and strong smoothing.

`moderate_mesh`: low face count and moderate smoothing.

`light_mesh`: medium face count and little smoothing.

These variants test whether the regularization of the projection surface affects orthomosaic stability.

### `n_orthos`

The number of orthomosaics analyzed for this variant.

In the current test:

```text
n_orthos = 2
```

This is enough to verify that the workflow runs and that repeated builds differ. It is not enough for a robust scientific stability estimate. With two replicates, the deviation metrics are still close to a pairwise difference. A serious test should use at least five replicates per variant.

### `grid_mode`

The canonical grid mode.

In the current test:

```text
grid_mode = union
```

This means the analysis grid covers the combined extent of all orthomosaics.

### `xsize` and `ysize`

The dimensions of the canonical analysis grid.

In the current test:

```text
xsize = 3647
ysize = 4047
```

These are not necessarily the dimensions of the original Metashape orthomosaics. They are the dimensions of the shared analysis grid.

### `any_support_fraction`

Fraction of the canonical grid where at least one replicate has valid image data.

Example:

```text
any_support_fraction = 0.740
```

This means that about 74 % of the union grid is covered by at least one valid orthomosaic pixel. The remaining area is outside the valid orthomosaic support.

This value is strongly affected by the chosen grid mode. In `union` mode, it is normal that the support fraction is below 1, because the grid includes the combined outer extent.

### `full_support_fraction`

Fraction of the canonical grid where all replicates of the variant have valid image data.

With two replicates, this means:

```text
valid in rep_001 and valid in rep_002
```

Example:

```text
full_support_fraction = 0.739
```

This means that about 73.9 % of the union grid is covered by both replicate orthomosaics.

The difference between `any_support_fraction` and `full_support_fraction` measures support instability. If the two values are nearly identical, the valid spatial support is stable. If they differ strongly, the orthomosaic extent or nodata pattern changes between replicates.

In the current test, the difference is small. This means that the border/support instability exists, but it is not the dominant difference between the tested variants.

### `mean_valid_count`

Average number of valid orthomosaics per grid cell.

With two replicates, possible pixel values in `valid_count.tif` are:

```text
0 = no replicate has valid data
1 = only one replicate has valid data
2 = both replicates have valid data
```

A `mean_valid_count` around 1.48 means that most valid pixels are present in both replicates, but the union grid also contains nodata regions.

### `min_valid_count` and `max_valid_count`

Minimum and maximum values in `valid_count.tif`.

In the current test:

```text
min_valid_count = 0
max_valid_count = 2
```

This is expected for two-replicate analyses on a union grid.

### `mean_mad_rgb`

Mean robust deviation from the median orthomosaic, averaged over RGB bands and valid pixels.

`MAD` means median absolute deviation. It measures how far the replicate orthomosaics deviate from the median image.

The unit is digital number on the image scale, here effectively the 0–255 RGB value scale.

Lower values mean higher repeated-build stability.

Current values:

```text
flat_mesh      5.63
light_mesh     4.60
moderate_mesh  4.28
```

In this test, `moderate_mesh` is the most stable variant by this metric. `flat_mesh` is the least stable.

With only two replicates, this metric should be interpreted cautiously. It is still useful as a technical diagnostic, but not yet as a final statistical result.

### `p95_mad_rgb`

The 95th percentile of `mad_rgb.tif`.

This value describes the upper tail of instability. It answers:

How large is the MAD in the more unstable 5 % of valid pixels?

Current values:

```text
flat_mesh      16.33
light_mesh     13.83
moderate_mesh  13.17
```

Again, `moderate_mesh` currently shows the lowest high-end instability.

### `mean_rmse_to_median`

Mean RMSE of replicate values to the median orthomosaic.

This is another measure of repeated-build deviation. Like MAD, it is expressed in image digital numbers.

Lower values mean higher stability.

Current values:

```text
flat_mesh      5.86
light_mesh     4.83
moderate_mesh  4.51
```

The ranking is the same as for MAD:

```text
moderate_mesh most stable
light_mesh intermediate
flat_mesh least stable
```

### `p95_rmse_to_median`

The 95th percentile of `rmse_to_median.tif`.

Current values:

```text
flat_mesh      16.39
light_mesh     14.02
moderate_mesh  13.33
```

This indicates that the most unstable local areas are strongest in `flat_mesh`.

## Interpretation of the current test

The current result does not show that stronger mesh smoothing automatically produces the most stable orthomosaic.

Instead, the current raised-bog test suggests:

```text
moderate_mesh is more stable than light_mesh
light_mesh is more stable than flat_mesh
flat_mesh is least stable
```

This is plausible. Too little regularization may preserve too much local geometric noise. Too much regularization may over-flatten the projection surface and introduce local displacement or blending differences around small objects such as ditch edges, deadwood, shrubs or isolated trees.

The current result therefore points toward an optimum of projection-surface regularization rather than a simple rule that more smoothing is always better.

## Important limitation

The current test uses only two replicates per variant.

This is enough to prove that:

```text
the runner works
the canonical grid works
the variants produce different pixel products
the analyzer produces meaningful first diagnostics
```

It is not enough to claim a stable ranking of variants.

A stronger test should use:

```text
at least 5 replicates per variant for a first usable comparison
10 or more replicates per variant for a robust stability distribution
```

## Meaning for change detection

The stability products should be interpreted as a doorkeeper before change detection.

A pixel or patch should not be treated as a reliable change-detection unit merely because it appears in a high-resolution orthomosaic.

A suitable change-detection workflow should first ask:

```text
Is this image area reproducible under repeated photogrammetric processing?
```

Only reproducible image support should be used for fine-scale change interpretation. Areas with low support stability or high repeated-build deviation should be masked or explicitly marked as uncertain.

For the current raised-bog use case, this is especially relevant for small structures such as:

```text
ditch edges
lying deadwood
sparse shrubs
isolated trees
small wet/dry surface transitions
shadowed microstructures
```

These structures may be ecologically meaningful, but they are also likely to produce local orthomosaic instability.

## Current methodological conclusion

The canonical-grid step is mandatory.

The first analysis confirms that Metashape orthomosaics can vary in raster support and pixel values across repeated builds. Therefore, repeated-build stability should be quantified before using UAV orthomosaics as spatial evidence for fine-scale interpretation or change detection.

The next technical step is to add stable and unstable masks derived from `valid_count` and deviation thresholds.
